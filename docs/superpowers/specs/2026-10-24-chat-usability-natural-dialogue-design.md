# Beta 1.2.1.5：Chat 可用性与微信自然表达

用户确认版本 Beta 1.2.1.5；确认从生成前的人设、识图材料和表达规则改进，不机械删句／删标点／强制固定条数。随后明确：不能保留最多两条的限制，真实交流可能连续很多条。

## UI 范围

1. 所有标准／拟人 Chat 标题栏不再渲染新对话按钮，侧栏新建入口保留。手机、平板嵌入与悬浮布局一致。
2. API 教程返回原来的模型选择页面，下一次返回才到设置栏目；系统返回和标题返回一致，不硬编码成一个固定模型分类。
3. 个性化的输入框入口没有副标题，顺序为：输入框、图标、字体、色彩、高级材质（含状态栏样式）、流光炫彩。复用已有卡片、阴影、主题色与动画。
4. 简洁输入框的加号菜单提供深度思考与联网搜索，复用完整输入框同一状态／能力判定／切换回调及长按行为。不能误改设置生效范围，或绕过拟人设置保存约束。

## 对话范围

- 微信聊天默认允许口语省略、短反应、标点单独表达和自然分条；明确正式文风／特定说话习惯优先。
- 不回放用户刚说的话作开场，不交代整条理解与决策过程。对没有交代用意的内容可以短问，不为续聊编造游戏、盗号、用户衣着等故事。
- 不把冷静／直率映射成高冷、拒人千里或反复赶人休息；人物边界和相处温度依据用户设定与真实上下文，不统一做成热情或冷漠。
- 图片分析和说话分工明确：识图只提供可见事实及不确定性，不能把图中人当成发送者，不能仅凭人脸确认现实人物身份；用户已提供的身份标签／自述保留为用户信息，不作为视觉认证。
- 不从角色性别或情侣关系强推用户性别；已有明确用户自述／记忆照常生效。
- 移除固定两条合并及任何同类软件条数截断。模型自然输出的一百条合成测试应完整经过解析／分条准备／发送计划；不通过硬塞一百条提示词、强制短句或复制朋友原话来制造效果。模型自身 token／平台协议限制需要区分，不假装不存在。
- 叙事模式保持叙事格式、台词强调及原文学习，不套微信口语规则。历史事实、记忆和明确人物风格仍保留；旧的不良口癖不是必须继续模仿的设定。
