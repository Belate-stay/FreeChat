# FreeChat Beta 1.2.0.5: tablet presentation and stable Chat

The user's detailed requirements are the design authority. Keep the existing Kotlin/Compose UI, app theme, phone layouts, draft/save protections and learning isolation. Do not commit, push, deploy or alter a database. Continue in the current checkout, preserving earlier unpublished work.

## Requirement mapping

1. Adapt first-use agreement, new-version notice and feature recommendations to tablet aspect ratios. Bound readable text and dialogs; on a wide recommendation screen place the live preview on the left and title, introduction and centered action on the right (user's follow-up). Keep every notice, acceptance rule and demo action.
2. Conversation selection covers retained old Chat content. Do not clear the old page before the incoming page is ready. Do not duplicate active chat/API side effects just to retain old pixels.
3. In embedded settings, remove only the redundant leading category icon/title from the detail body; category list and navigation title remain. Keep meaningful internal section labels and phone headings.
4. Floating windows use the existing app card/input shadow vocabulary, not a new heavy black dual shadow.
5. Fullscreen controls exist only on actual Chat. No controls on sidebar, settings/categories/details, favorites, role creation, rules or model pages.
6. Actual Chat measurement width is stable when entering/exiting fullscreen or opening embedded rules/character settings. The auxiliary pane equals the home sidebar width, not half the screen. Move a stable-width Chat column rather than animating its text measurement constraints. The user confirmed the unchanged column is centered in fullscreen, with extra space left at both sides.
7. Leaving settings/favorites always returns to the underlying Chat, never Account, including Account -> settings/favorites.
8. Conversation switching leaves the composer shell in place, retaining its hidden/shown state and per-conversation draft storage. Animate draft contents only. Keep voice routing, keyboard/cursor behavior and send/edit protections intact.
9. Every floating window has one top-right X which closes the whole destination at any depth. Root has no redundant Back arrow; nested screens retain Back. The user explicitly confirmed keeping the existing discard/continue-editing confirmation for unsaved model and character forms; confirming discard closes the entire window.
10. Tablet preferences use one Page display item with the standard selection sheet: Floating / Embedded. Floating conditionally reveals Floating position (Both / Left / Right) and Underlying touch in the same card and disclosure animation as existing settings groups. Underlying touch defaults on and persists. Closed children retain their values.
11. With underlying touch enabled, the undimmed/unblurred base is usable while a floating window remains open, including switching the base conversation. With it off, block base input/focus/Back handling; learning remains exclusive regardless of this preference.

## Follow-up: readable recommendations and coordinated display size (2026-10-17)

The user requests larger recommendation text and UI/layout/DPI changes when selecting a font-size preset. Implement application-local display scaling, not a device-wide density change. Preserve the five existing stored FontSize values and their physical text scale: multiply Compose density by the preset once and use fontScale 1, so dp cards, gaps, radii, icons and sp text scale together. Provide a copied app-local Configuration with matching available dp dimensions; never mutate Resources, system settings or physical tablet identity. MainActivity's phone drawer geometry uses the same conversion as its rendered content. Legacy text-only dp compensation must not apply a second multiplier. Font-size preview must show the selected size once, not selected size multiplied by the current size.

Recommendation text uses an explicit readable hierarchy: tablet title 28sp, introduction 18sp/30sp, action 18sp; demo chat text 16sp/26sp, with secondary status text 14sp. Phone headings and body are increased modestly within their existing layout. Keep normal tablet landscape preview-left/introduction-right and a stacked, scrollable fallback when the scaled window cannot fit both. The demonstration can scroll instead of clipping larger text or the generated picture, and follows its completed content to the bottom. Keep its real components, exact timeline, disabled interactions during playback and completion gate. No new scale preference or third-party dependency.

Native Dialog/Popup roots must inherit the caller's display density/configuration too. On live scale changes, keep composition/state stable and derive constraint dp from the latest density and unchanged pixel constraints; do not rebuild the whole app with a font-size key. Reuse the existing compact drawer footer for scaled narrow phone widths (including English labels). Avatar cropping must use the actual remaining preview area after the hint/actions are measured, and the same rendered square pixel side for preview, gestures and saved crop. Verify these edge cases, not only cold starts at each preset.

At narrow scaled widths, measure complete-composer labels in the active font and use the same icon shortcuts with accessible names only when the full labels would cover the microphone; leave normal-width labels unchanged. Keep emoji availability restricted to WeChat, fit its columns to the actual width and scroll the height-bounded grid instead of clipping cells. Fit only overflowing welcome lines to their available width; preserve normal short-greeting typography and the existing keyboard transition.
