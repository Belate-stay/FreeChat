# FreeChat Beta 1.2.1.6：角色池与多角色群聊设计

状态：已按用户确认的分角色方案实现并完成本地验证与打包；群模型以用户后续指定的统一群设置为准。验证范围及部署边界见 `_verify/v1216/VERIFICATION.md`。

## 已确认的需求

- 角色卡可独立于对话存在，版本为 `1.2.1.6`，versionCode 接续为 `265`。
- 设置的“模型选择”下方新增“我的角色”，保存角色卡和一层文件夹；角色可移动。
- 创建角色有“开始对话”和“存入角色池”两个出口。直接开始对话不自动入池；已有对话里的角色可以显式添加到池中。
- “选择对话模式”的微信聊天下增加“多角色群聊”子项，从池中逐个选角色或按文件夹选择。
- 群最多含用户和四名角色，不能通过导入、同步或编辑绕过人数限制。
- 群聊由用户消息触发，不启动后台主动智能，不自动发送各角色的开场白。
- 用户已确认：创建对话时复制人设，各个单聊／群聊的记忆独立；编辑角色卡不自动修改已有对话。
- 用户已确认：角色池与文件夹参与账号同步；服务器只本地修改，不部署。旧服务器未升级时先安全保存在本机。

## 两种实现方式与推荐

推荐“群聊编排＋分角色生成”。一次用户发言开启一个有限的回复计划，编排器依据公开群聊历史、成员性格和关系，决定谁有理由开口、顺序及接话对象；真正的回复使用当前发言者自己的完整设定和记忆，统一调用本群指定的语言模型，未指定则实时跟随全局。先生成的消息先显示。这样能隔离身份和私密设定，代价是通常需要多次模型请求。

另一方式是一次请求扮演所有角色，调用更少、整体等待较短，但所有设定集中在同一个上下文里，更容易混淆人格和私密信息。本版不推荐作为默认实现。角色卡不保存模型，单聊和群聊的模型选择属于各自 Part 2。

不增加 AutoGen 等运行框架依赖，复用现有 Kotlin、OkHttp、存储、流式请求和 Compose 组件。

参考依据：SillyTavern 将“按发言者切换角色卡”和“拼接所有角色卡”区分，并提示后者可能混淆人格；AutoGen 的 selector group chat 展示了按上下文选择发言者和显式结束任务的方式。仅借鉴机制，不照搬随机话痨概率、固定轮询或后台自动循环。

## 角色池与文件夹

角色卡只独立保存 Part 1：名称、头像、原始人设、人物信息、MBTI、人物关系、用户填写的前提资料与已有角色学习结果。它不保存 Part 2 的语言／识图／生图模型、主动智能、回复缓冲、时间感知、思考／联网开关或其他模式回复参数，也不包含来源对话的聊天记录、动态记忆或 API Key。来自已有对话的角色是显式提取 Part 1；原对话随后修改或删除，不影响卡片。

“我的角色”提供创建角色、添加已有角色、查看／编辑、移动和删除。文件夹可创建、重命名、删除，但不嵌套。无文件夹角色显示在“未分类”。删除文件夹时将卡片移到未分类，确认文字明确说明，不连带删除角色。删除卡片不删除已经建立的单聊／群聊。

创建流程保留现有角色学习、必填验证和全屏学习页。学习成功后，按用户选的出口仅创建对话或仅保存卡片。存卡时选择文件夹，也可直接放未分类；取消选文件夹或学习失败不产生空卡片／空对话，输入继续保留。已有对话导入池时复用已有设定，不重新编造人设。

卡片编辑沿用预览／编辑和保存机制，只展示 Part 1，不假装存在可以保存的 Part 2。卡片人设变化需要保存后学习，仅影响以后从此卡新建的对话。人物学习输出也须专注人物本身，不把某个对话模式的行为开关编入角色卡。

从卡片创建对话时，Part 1 复制成对话快照，Part 2 由微信私聊、微信群聊、动作演绎、剧情补足各自的默认设置创建；不能从来源对话、最近一次使用或别的群偷带设置。旧的单角色 Conversation/CharacterProfile 结构向后兼容，不为此重写已有对话。

## 群聊创建与显示

“多角色群聊”是微信聊天的子选项，不增加第四种 DialogueMode。勾选后进入角色选择，可浏览文件夹、整夹勾选、逐卡勾选，显示已选人数和头像。选中按卡片 ID 去重。

文件夹选择在未超过四名角色时一次加入全部。超过剩余额度则保留原选择，并提示从该文件夹逐个选择，不偷偷只取前四个。没有角色不能开始；一至四名角色均可建立，人数含用户显示为二至五人。

开始时创建独立群聊，并为每个成员保存人设快照及稳定成员 ID。群聊中成员用微信聊天形态回复，池中卡片的原默认模式和设定不被改写。

群名可沿用现有对话重命名；群设置可查看成员、加入或移除成员、查看／编辑本群成员快照和设置本群公共规则。群成员形态固定为微信聊天，不能在本群成员编辑页切到叙事模式。群成员设定和成员列表修改均需保存，群思考／回复期间禁用保存；池中独立卡片的编辑不受此影响。加入成员依然从角色池选择并检查四名上限。

左侧角色气泡显示该发言者头像与群成员昵称，用户消息仍在右侧。“显示群成员昵称”关闭时只隐藏消息旁的名称，头像保留，标题栏的对话备注不受影响。发送者使用稳定 ID，而不是依靠模型把姓名写在正文里。重名不导致串人，改群名、移动卡片不改历史发言归属。手机、平板嵌入和悬浮布局复用已有材质、主题、缩放与动效。

长按成员头像插入绑定成员 ID 的 @，不能仅按重名文字猜目标；用户删掉 @ 后不能残留隐藏的点名。双击头像产生公开的“拍一拍”系统事件，并可引起本轮注意。@ 和拍一拍都提高相关角色被选中的可能，但不强制在线、唤醒或回复，不替角色生成固定回应。

群设置不提供主动智能或接入外部微信机器人入口。本版多角色群聊在 FreeChat 内运行。

### 用户补充的群聊设置

群聊标题栏最右侧的调节按钮进入独立“群聊设置”，布局借鉴微信聊天信息页，同时采用现有 FreeChat 卡片、圆角、材质与动画。

- 顶部为成员头像与名称网格，含用户和角色，另有加入／移除入口。点击角色进入该成员在本群的提示词设置，保存只影响此群；点击用户可编辑本群昵称。不能打开或改写角色池原卡片来冒充群成员编辑。
- 群聊名称是用户给这个对话的备注，与对话标题一致，不自动当作所有角色已知的群内事实。
- 群公告通过独立编辑／发布提交，保留原文和更新时间，并在群内以系统提示呈现；各成员后续请求都读取当前已发布公告。公告文字是用户发布的群内资料，不能覆盖上层人设或系统规则。发布公告本身不启动后台角色聊天。
- “我在群里的昵称”是该群专属的用户显示身份，供群消息和角色理解称呼使用；不修改全局账号名或其他群。不能因为改昵称而把历史用户当成新成员，用户 ID 保持稳定。
- 置顶聊天复用现有对话置顶；查找聊天记录限定在当前群；显示群成员昵称控制气泡旁名称的显示，默认开启，不改变模型的发送者归属。
- 群聊头像支持用户单独设置和清除；默认由一至四名角色头像组合，成员变化时更新组合头像，不修改角色头像。自设头像在成员变化时保持，清除后恢复组合。
- 群聊提供语言模型和识图模型设置，默认实时跟随全局；本群编排与所有成员生成统一使用群语言模型，群内图片统一使用群识图模型。群成员页不提供与其冲突的独立模型、主动智能或回复缓冲项。
- 群名、公告和昵称各自进入编辑页并确认保存／发布，未提交的输入不影响聊天。成员列表、人设、公告和昵称的提交在群回复进行时有明确等待提示；群备注和置顶属于用户显示偏好，不影响已开始的模型请求。
- 平板仍遵循用户选择的嵌入／悬浮显示；头像网格、二级编辑页和返回方向适配大字号与横竖屏。

## 回复编排与真人感

用户后续已明确选择“群聊始终统一用群设置，默认跟随全局”。编排器和所有成员使用本群语言模型，本群未指定时实时读取全局；识图同理。单聊和池中 Part 1 不受群模型变化影响。已失效的自定义模型 ID 继续使用现有解析／报错路径，不把 API Key 复制到角色卡。

群级深度思考／联网／回复缓冲等属于微信群聊自己的 Part 2，不改写私人对话或全局，也不读取卡片中的旧字段。公共图片观察只识别一次后提供给实际参与本轮的角色；每位角色仍用自己的 Part 1 及独立记忆表达。

编排考虑是否被点名、是否被拍一拍、话题相关性、既有人物关系、当下情绪、最近发言、生活状态和性格。允许暂不在线、忙碌、不想回复、全员暂未回应、仅部分人发言、短反应、不同频率、接前一个人的话，以及同一成员再次接话；不按名单轮流报数，不要求每人都答，不强制每人一条，也不恢复“两条”合并。不凭随机数给角色编造“离线”状态，明确沉默不是请求失败。

调度只产生本次用户输入所触发的有限计划，计划执行后结束，不因角色消息开启新的后台轮次。相邻同一成员的计划可用一次生成完成，其生成出的自然气泡保留；模型／网络的正常资源约束继续生效，不删除已写出的内容来凑条数。

编排结果只传稳定成员／目标消息 ID，不将编排器的私密推测或其他成员人设转发为角色已知事实。成员只收到自己的完整人设、自己的记忆、公共规则、真实群消息及可见的成员名称。角色不能代写他人台词、替用户发言，不能知道另一个成员未在群里透露的秘密。

既有去 AI 味规则继续作用于微信聊天：按人设与关系自然表达，不机械复述、解释自己的分析链或补造用户动机；正式文风角色仍优先还原。

## 上下文、记忆、取消与错误

消息增加可选的成员归属字段，旧单聊字段默认不变。每个发言者看见自己的旧消息为自己的发言，其他成员以带真实发送者标识的群消息进入上下文，避免把所有 assistant 消息当作自己说的。

同群公开发言所有成员可见；各成员的身份、见闻、情绪和约定按成员 ID 隔离。不同对话之间不传记忆。图片在本轮识别后作为公共观察资料复用，同时保留现有图片来源边界；不把角色的私密资料当作公共群消息。

用户继续发消息、点击停止或删除触发消息时，取消未完成的请求和待发送计划。已送达的群消息保留；新一轮读取这些实际发言，不重复回答已经说完的内容。对话切换遵循现有后台／焦点策略，不能将结果写到当前碰巧打开的另一个对话。

单个成员失败只标记该成员的失败，不伪装成正常角色台词、不删除其他人已经成功的消息；可重试该失败项，不能重复整轮已成功发言。模型返回未知成员、结构不合法或网络失败时按实际错误反馈，不随机冒充一个人兜底。

删除消息时仍清除其派生记忆；删除群聊时删除群消息、成员记忆、设置与本群媒体引用。删除卡片／文件夹不清除已有对话的快照。

## 本地与云端数据边界

新增独立角色卡、文件夹对象及本地仓库，仍通过 LocalStore 原子写入和现有同步监听工作，不把假角色卡伪装成隐藏聊天记录。群聊快照、发送者和成员记忆随原对话对象同步。

角色卡与文件夹同步使用对象 ID、版本、删除记录和明确冲突处理，不采用整池最后写入覆盖。删除不能因旧设备推送复活。同一卡片的不同人设并发冲突保留双方版本，以冲突副本明确展示；相同内容去重。文件夹被删除后，仍指向它的卡片归入未分类，不删除卡片；同时移到另一个有效文件夹的卡片保留其新归属。同步尚未拉到文件夹时先保留引用，不能把暂时未到达误判成用户删除。

头像／参考图的保留引用覆盖角色池、群成员和对话。卡片与对话复用同一张图时，删除任何一方都不能误删另一方仍使用的图；最后引用删除后才回收载荷。服务器需同步更新图片引用检查，但不修改真实数据库结构。

服务器通过可读能力信息表明已支持角色池的图片引用规则。旧服务器未声明支持时，新角色池内容先本机持久保存并等待同步；不影响原对话同步，不冒险上传随后可能被旧回收器误删的引用。

本版以 Android 功能为主，Web 数据类型／同步需保留新对象和发送者，不得把新群聊当旧单角色对话覆盖保存。兼容层必须明确处理不支持的操作，不静默丢成员。完整 Web 角色池管理界面不作为本次 Android 页面验收项。

## 可验证的验收标准

1. 存入角色池不增加对话；直接开始对话不增加角色卡；取消、学习失败不产生半成品。已有对话添加到池不修改原聊天和记忆。
2. 一层文件夹增删改、移动、整夹选择、去重和超过四名时的行为都有回归。已有设置栏目索引保持兼容。
3. 用同名成员、四种明确不同人设和多个对话验证归属。群计划中沉默、离线、单人参与、接话和重复成员不变成固定轮询，100 条自然气泡仍完整保留。@／拍一拍绑定正确成员但不强制回复；清除文字能清除点名。
4. 使用伪模型验证群模型统一解析、人设隔离、上下文、记忆和公开图片只处理一次。卡片 JSON 中不存在模型、主动智能、缓冲或其他 Part 2 字段。从同一卡片建立不同模式对话不会继承来源对话设置；不能向 B 的请求泄漏 A 的秘密或跨群记忆。
5. 用户连续发送、停止、切换对话、单人成败混合、失败项重试和删除时不重复成功消息，不出现迟到结果复活。
6. 新旧 JSON 往返、同步冲突、文件夹删除／移动竞态、角色图像引用回收和旧服务器能力缺失都有离线测试，不修改真实数据库。
7. 手机与横竖平板、嵌入／悬浮、深浅色、大字号实查选择器、角色池和群消息。现有单聊、叙事、输入框、标准模式和构建回归继续通过。
8. 版本 `1.2.1.6` / `265`，Debug／Release 构建、签名与无 QA 组件校验完成，结果如实记入本版验证目录。

真实模型调用须另获有限测试额度；此前八次授权已用完，不在本版自动追加付费请求。真人感既做请求与发送路径回归，也如实区分合成验证和真实模型表现，不承诺消除模型自身全部偏差。

## 范围约束

不修改既有单角色对话的保存语义，不把群成员自动加入角色池，不添加多层文件夹、后台自主群聊、外部微信群机器人接入或第三方角色卡协议。使用现有角色设定和导入入口。只修改本地服务器／Web 配套代码，不部署、提交或 Push，不写全局记忆文件。
