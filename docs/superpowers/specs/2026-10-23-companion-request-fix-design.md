# Beta 1.2.1.4：拟人请求失败修复

用户已确认按诊断根因修复，版本为 Beta 1.2.1.4。动作演绎／剧情补足在开启联网工具时，正常回执里的 `tool_calls: null` 被 Gson 强转数组，变成泛化的“请求失败”。本地用 12 份既有人工场景回执已复现；手机截图中的联网状态与错误文案吻合，但没有手机异常堆栈，不能声称所有失败都由同一原因造成。

## 已确认的方案与边界

- 保留增强检索、深度推演、深度思考、人设、记忆及现有非流式调用协议。不靠关闭功能、截断正文或新增付费模型请求绕过故障。
- 工具调用统一按 JSON 元素类型读取：缺失、null、空数组都代表没有工具调用，数组中的真实工具调用保留。Android 拟人正式生成和标准流式／非流式回退共用这一个读取点。
- 叙事篇幅补写失败或没有有效正文时保留原回复（包括推理与来源）；取消必须继续向外传播，不能迟到落库。
- 复用现有 OkHttp／协程依赖，使拟人 HTTP 请求在取消时终止连接。记录推演、正式回复、篇幅补写、格式修复各次请求的单调时钟耗时与状态，不记人设、聊天、Key 或地址。
- 本地服务器修复模型代理与普通接口混用的短空闲超时；普通登录／同步接口维持原限时。只改本地代码与部署模板，不部署、重启、提交或 Push；数据库不改。

## 验证标准

1. 使用 Gson 2.11.0 对 null／缺失／空数组／实际工具／流式增量运行真实单元测试，不以源码字符串检查代替解析行为测试。
2. 用合成回复测试补写异常、空回复、成功替换及协程取消，确认原正文／推理／来源没有丢失。
3. 本机 MockWebServer 验证延迟正文、非 2xx 回执、读取异常与取消；不请求真实模型。
4. 服务端本机假上游／临时库测试与部署模板检查，明确区分运行时行为与静态配置检查。
5. 运行 Android、共享核心和微信大脑回归测试，构建 Beta 1.2.1.4 Release 包并验证版本与签名。现有脏工作区的其他修改保持不变。
