# FreeChat Beta 1.2.0.2 平板自适应设计

日期：2026-10-15。目标版本：Beta 1.2.0.2。

基线：当前工作区 Beta 1.2.0.1，保留 Claude Code 已完成及尚未提交的改动。
本文记录平板改造及已确认的保存语义，尚未实施产品代码。

## 1. 目标与边界

- 平板横屏、竖屏均使用平板布局，不把手机 UI 等比放大。
- 默认双栏，按页面任务组织列表、详情、聊天和辅助工具；相关面板支持单独全屏及恢复分栏。
- 保持现有主题色、深浅色、高级材质、新拟态、流光炫彩、字体与动效语言。
- 手机仍使用现有导航和布局。修正模拟设置的保存语义适用于共享业务路径，不限定平板。
- 不修改模型请求协议、同步协议、服务器、数据库或开发者核验机制，不部署，不重构无关代码。
- 不新增第三方主题系统，不默认增加第三个内容栏，不增加用户未要求的多窗口会话功能。

## 2. 已确认的操作语义

### 2.1 聊天与辅助设置

用户选择方案 1：从聊天打开新规则或模拟设置时，左侧保留当前聊天，右侧打开设置；对话列表暂时让位。关闭辅助设置后恢复对话列表与聊天的常规双栏。

设置必须绑定打开时的对话 ID，不能因为当前对话状态变化而误写另一个角色。离开有未保存修改的模拟设置时走统一的未保存确认流程，不隐式提交。

### 2.2 新规则：即时生效

- 编辑直接写入该对话的新规则和覆盖设置，不增加保存或确定按钮。
- 已发出的模型请求继续使用该轮已构建的上下文；后续请求读取更新后的规则。
- 分栏、全屏切换和返回均不额外触发写入。

### 2.3 模拟设置：两部分均显式保存

- Part 1 为角色设定、提示词等人物资料；Part 2 为功能开关、模型选择等模拟功能设置。
- 两部分的修改都先保存在表单草稿中。只有用户明确点击保存动作才能提交。
- 点击保存之前，旁边的聊天仅使用已保存的角色档案、提示词和功能配置，不读取草稿。
- 返回、横竖屏变化、全屏切换、展开选项、关闭弹层都不能自动保存。
- 取消或放弃修改不能改变已保存档案，也不能因为 Part 2 有改动而偷偷保存它。
- 只修改功能项时保存直接生效，不额外触发角色学习；修改人物设定时沿用人设更新与学习流程。
- 字段分类以人物设定和功能设置的真实边界为准，模型选择和思考开关不能被误判成人设变化。

### 2.4 角色思考或回复时禁止保存

用户明确指定：角色思考或回复中，模拟设置的保存按钮置灰，显示：

> 请等待角色思考/回复完毕后保存更改

- 草稿仍允许编辑并保留，不把整张表单禁用。
- 页尾保存、页头保存入口、二次确认中的保存以及实际提交回调共用相同的忙碌判断。
- 禁止点击、键盘操作、重复点击或延迟确认绕过禁用。
- 判断针对当前正在编辑的角色，而非其他无关对话。
- 本轮结束后恢复正常保存按钮；不排队自动保存、不自动开始学习、不打断当前回复。
- 中文文案使用用户给定原文，并为既有繁体中文和英语界面补齐对应表达。

### 2.5 AI 学习全屏独占

- 创建角色或保存人物设定后，若需要 AI 学习，学习页面占据整个应用窗口，不保留可操作的双栏聊天。
- 学习期间不能通过聊天输入、返回、侧栏、全屏切换等路径重新进入该角色聊天。
- 学习结束后恢复相应聊天；失败沿用明确的错误反馈和可恢复路径，不把未完成的学习当成功。
- 单纯保存 Part 2 的功能设置不制造学习请求或等待动画。

## 3. 页面组织

| 场景 | 左栏 | 右栏 | 全屏用途 |
| --- | --- | --- | --- |
| 常规聊天 | 对话列表、搜索及现有导航入口 | 当前对话、输入框、定位条 | 专注聊天或管理长列表 |
| 聊天中的新规则 | 当前聊天 | 即时生效的新规则 | 专注编辑或阅读聊天 |
| 聊天中的模拟设置 | 当前聊天，使用已保存档案 | Part 1 / Part 2 草稿及保存入口 | 长人设编辑 |
| 全局设置 | 分类与目录 | 当前设置内容 | 复杂设置和长内容 |
| 模型管理 | 当前模型池 | 所选模型详情或添加/编辑表单 | 较长的模型配置 |
| 收藏 | 收藏列表、筛选与多选 | 收藏详情 | 长消息阅读 |
| 创建角色 | 角色设定 | 功能配置 | 任一部分的长表单 |

分享、反馈、账号、语音及阅读页面根据已有任务结构采用合理限宽、分组和详情展示，不仅把一列拉宽。图片预览仍可全窗口沉浸显示并保留已有图片切换与开合过渡。

## 4. 自适应与尺寸

- 采用 Android 官方窗口、自适应布局能力，优先复用 Material 3 Adaptive 的列表详情及辅助面板模式。
- 结合设备的大屏能力与当前可用窗口尺寸。手机横屏不能仅因为窗口变宽就被误认成平板。
- 平板横竖屏维持相同导航与工作流；栏宽随实际可用空间调整，不把字号和按钮按宽度等比放大。
- 对话正文、输入框、长表单和阅读内容设置合理的最大行宽；列表允许比手机更高效的信息密度，仍保留足够触控区域。
- 使用真实系统 density 与 dp/sp；保留现有字体和应用字号偏好，不伪造 DPI 来制造平板布局。
- 当系统分屏或自由窗口窄到无法容纳可用的双栏时，保留平板的导航和业务状态，临时显示当前焦点面板；恢复空间后回到分栏，不溢出或裁掉必要操作。
- 快速定位、菜单锚点、输入框高度及键盘避让均以所在面板尺寸为依据，不继续套用整块屏幕宽高。

## 5. 状态、材质与动画

- 复用同一业务 ViewModel、会话视口记录、草稿和选择状态；切换全屏与分栏不重发 API、不重建角色、不丢弃未保存表单。
- 选中项目、当前对话与辅助设置对象保持一致；不会把表单草稿写入聊天上下文。
- 各栏拥有正确范围的模糊采样、标题触控隔离和裁剪。弹层限宽并在相关面板内定位；全局确认和学习页则覆盖全应用。
- 流光背景共用现有时钟和坐标链，避免每栏独立启动造成色块接缝或相位错位。
- 使用已有动效规格与非线性曲线。只动发生变化的面板，不让无关栏跟着重播转场。
- 分栏/全屏过渡保持空间连续，避免双份重型模糊长时间并存；不得通过临时切回白色实底来优化转场。
- 保留减动效支持、主题语义色、正确的禁用状态和无障碍标签。全屏按钮使用现有图标风格与触控尺寸。

## 6. 可验证的验收标准

1. 手机竖屏及横屏仍走原有手机布局，无平板专用栏位泄漏。
2. 平板竖屏和横屏默认双栏；旋转、调整窗口和 DPI 后无横向溢出或被遮挡的必要按钮。
3. 对话列表选择、历史搜索、多选、收藏、模型选择和各级返回功能正常。
4. 分栏/全屏往返保留聊天阅读位置、输入草稿、角色表单草稿和页面选择；不重复调用模型。
5. 新规则修改后，下一轮请求可读取新规则；不需要保存按钮。
6. 模拟设置分别修改 Part 1、Part 2、两者混合，保存前聊天请求均使用旧档案。
7. 模拟设置返回、切换全屏或旋转均不提交草稿；明确放弃后旧档案不变。
8. 角色正在思考和正在逐条回复两种状态都禁用保存；显示指定中文文案；提交回调也拒绝保存。
9. 角色回复完成后恢复保存，草稿保留；不自动保存或进入学习。
10. 仅功能项变更保存不触发学习；人物资料保存按正常学习流程执行。
11. 学习页面覆盖全应用，所有返回或导航绕行均不能恢复该角色的输入入口；结束后正常恢复。
12. 深浅色、黑白/彩色主题、高级材质开关、流光开关组合下，栏位、阴影、圆角、标题模糊和弹层一致。
13. 键盘仅挤压需要避让的面板；长文本光标可见，另一栏没有无关跳动。
14. 快速定位按聊天栏实际尺寸估算并随拖动正确定位；菜单不跑到其他栏或屏幕外。
15. 现有 JVM 回归、编译、APK 版本及签名检查通过；模拟器截图与录屏覆盖手机、平板横竖屏、全屏和学习态。

真实设备帧率和触控体验需有对应设备才能验证，不以软件 GPU 模拟器录像宣称真机 60/120fps 保证。

## 7. 已识别的代码接入点

- `MainActivity.kt`：当前单页路由、90% 屏宽抽屉、全局材质与学习页；需要加入平板宿主及全屏独占路由。
- `CharacterSetupScreen.kt`：表单草稿已局部保存，但 `requestBack()` 仍自动调用 `onSaveSimulation`；需要移除隐式保存，统一所有保存入口和忙碌保护。
- `NewRulesScreen.kt`：现有即时写入路径保留。
- `ChatScreen.kt` / `ChatInput.kt` / `ChatQuickLocate.kt`：替换平板分栏内使用整屏尺寸的估算，维持手机路径。
- `SettingsScreen.kt`、模型、收藏等相关页面：复用现有内容，调整导航和分栏，不复制一套业务状态。
- `TopBarBackdrop.kt` / `SheetPanel.kt` / 材质与动效组件：按面板范围正确采样、定位与交互隔离，延续现有视觉链。
- i18n、版本与开发更新日志：完成实现和验证后同步更新至 Beta 1.2.0.2。
